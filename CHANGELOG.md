# Changelog

## Unreleased

Phase 1 complete (5 Nov 2026): image, video and audio conversions from the wheel, job queue, failure toasts, golden tests, logging and tray icon.

Phase 0 (spikes) complete: drag wheel, image and video conversion in a sandboxed worker, MSIX packaging.

### Added
- Sheets, subtitles and archives (task 2.6): CSV ↔ XLSX, SRT ↔ VTT, and ZIP, TAR and TAR.GZ among each other on the Convert wheel (10 rows; new XLSX, CSV, SRT, VTT, ZIP, TAR and TAR.GZ wedges). CSV → XLSX makes one sheet with numbers as numbers and everything else as text, never a formula; comma, semicolon and tab CSVs are recognised. XLSX → CSV writes one CSV per sheet (`book-Sales.csv`, or `book.csv` for one sheet) with formula results and dates as `2024-01-31`, in UTF-8 that Excel opens correctly; text that Excel would run as a formula gets a leading apostrophe. SRT ↔ VTT keeps bold, italic and underline and drops other styling; old Windows-1252 files read correctly. Archives are re-packed file by file without unpacking to disk; a `.gz` with one plain file inside becomes an archive holding that file. Archives with unsafe paths (`..\`, `C:\`) fail; over 100,000 files or 10 GB unpacked stops. No new dependencies (Open XML SDK, System.IO.Compression, System.Formats.Tar). `gen-fixtures.cs` writes the same grid, cues and files in each format (XLSX as hand-written XML); golden tests compare against hand-written expectations. `DataEngineTests`: unsafe paths, plain `.gz`, CSV formulas and semicolons, Windows-1252 SRT with font tags, VTT voice tags.
- PDF to Word, beta (task 2.5): dropping a PDF offers DOCX on the Convert wheel, marked "beta" on the wedge (CV-5; the first beta row, so the wheel now draws the mark). The document is rebuilt from the PDF's text: headings by font size, paragraphs with wrapped lines joined, bold, italic and links, bullet and numbered lists with nesting (also bullets drawn as shapes, as browsers print them), monospace blocks as code; page numbers are dropped. Tables come out as paragraphs and images are left out; a scanned PDF fails with "has no text". PDFs up to 500 MB and 2,000 pages. New dependency: PdfPig 0.1.16 (Apache-2.0). Tests: Markdown → PDF (WebView2) → DOCX keeps the exact structure; scanned PDF; golden row on the sample PDF.
- Documents to PDF (task 2.4): DOCX, Markdown, HTML and TXT get the PDF wedge on the Convert wheel (4 rows). The document is laid out as Morph's HTML page and printed to an A4 PDF by WebView2 (part of Windows 11) on a hidden window; the page is served from memory, every other request is refused and scripts are off, so it never goes online. When Word is installed, DOCX → PDF uses Word's own PDF export for an exact layout (a temp copy, read-only, macros off; Word quits afterwards unless the user has documents open in it). Document jobs may run up to 16 processes in the Worker's Job Object (was 4). New dependency: Microsoft.Web.WebView2 1.0.4258.31 (BSD-3). Golden tests read the PDF's text back through PDFium. The Word path is untested here (no Word on the dev machine).
- Documents (task 2.3): DOCX, Markdown, HTML and TXT convert among each other from the Convert wheel (12 rows; new DOCX, MD and HTML wedges, TXT reused). Each file is read into one small block tree (headings, paragraphs with bold/italic/code/links, nested lists, tables, code blocks) and written out, so a new format needs one reader and one writer. DOCX is read and written with the Open XML SDK using Word's own style names (Heading 1-6, List Paragraph, Table Grid, Hyperlink); headings, lists and code are recognised by style, numbering and font. HTML is read by a small forgiving tag scanner (scripts and styles dropped) and written as a standalone page; Markdown is CommonMark + pipe tables (Markdig), with text that looks like markup escaped. Links other than web, mail and relative ones are dropped. Images, quotes and page breaks are not carried over yet. Empty, damaged or over-50 MB files fail with a plain reason. New `DocumentEngine` (engine id `document`). New dependencies: DocumentFormat.OpenXml 3.5.1 (MIT, pulls System.IO.Packaging) and Markdig 1.6.0 (BSD-2). `gen-fixtures.cs` writes the same sample as `sample.docx` (hand-written XML, not Morph's writer), `.md`, `.html` and `.txt`; golden tests check the full structure after each conversion (words only to or from TXT). `DocumentEngineTests`: DOCX output passes the Open XML validator, HTML script stripping and entities, unsafe links, Markdown escaping, empty and damaged input.
- Morph glass look (developer's call): the wheel, toasts and the merge window are warm frosted glass with a Morph orange accent (#C94F0E light, #FF9A5C dark) instead of the Windows accent, light or dark with Windows. The wheel blurs a snapshot of the screen behind it (layered windows can't get DWM blur; show measured 13-15 ms with the snapshot); toasts use Windows' blur-behind accent with DWM rounded corners and shadow (no longer layered); the merge window uses the Windows 11 acrylic backdrop. With transparency effects off, all three use solid warm colours. New `Morph.Overlay.Theme.MorphGlass` and `Morph.App.Theme.MorphTheme`; one hand-written `SetWindowCompositionAttribute` import (undocumented, no metadata for CsWin32). Checked by hand through harnesses over a colourful backdrop: wheel light and dark, toast and merge window dark.
- Merge order window (developer's call): dropping on Merge opens a small Fluent window, "Merge into one PDF", listing the files in drop order with a number, a PDF or image icon and move up/down buttons per row; Merge runs the job in the chosen order, Cancel or Esc runs nothing. Keyboard: Tab to a button, Space moves the row and focus follows it; Enter merges. Interaction inspired by the Tangerine reference, not its look. Checked by hand through a harness and UI Automation: reorder, Merge returns the new order, names read by screen readers.
- Images to PDF and merge (task 2.2): JPG, PNG, WebP, GIF, BMP, TIFF, HEIC and AVIF get a PDF wedge on the Convert wheel (one PDF per image, `photo.pdf`). Dragging two or more PDFs and/or images and tapping Ctrl offers Merge: one PDF in drop order next to the first file (`report-merged.pdf`). Image pages take the image's DPI (else 96), shrunk to fit A4's long side; EXIF rotation applied. A password-protected or damaged PDF fails the merge with a plain reason; over 2,000 pages is refused. Tools wheel: `capabilities.json` tools now come first, before the placeholder wedges; new `minFiles` tool field. New dependency: PDFsharp 6.2.4 (MIT), with System.Security.Cryptography.Pkcs pinned to 10.0.13 (transitive pinning on) because PDFsharp asks for a vulnerable 8.0.1. Golden tests: 8 image → PDF rows rendered back through PDFium and compared by dHash; merge of PNG + 2-page PDF + JPG gives 4 pages in order. `PdfEngineTests`: password-protected PDF in a merge.
- PDF to JPG, PNG and TXT (task 2.1): dropping a PDF on the Convert wheel offers JPG, PNG and a new TXT wedge. Each page becomes one image at 150 DPI next to the original (`report-1.png`, `report-2.png`, …; a one-page PDF gives `report.png`); TXT holds the text of every page, a blank line between pages. A scanned PDF with no text, a damaged or password-protected PDF, or one over 2,000 pages fails with a plain reason. New `PdfEngine` (engine id `pdf`) on PDFium through ~20 hand-written `LibraryImport`s. New binary: PDFium chromium/8125 from bblanchon/pdfium-binaries (BSD-3/Apache-2.0, 7.6 MB), fetched and SHA-256-checked by `build/fetch-binaries.ps1`, which now handles several pins; `pack.ps1` requires it. `gen-fixtures.cs` writes a two-page `sample.pdf`; golden tests check page count, size (450×300), a red box per page and the extracted text (121 rows). `PdfEngineTests`: damaged PDF.
- Logging and tray icon (task 1.9): Morph writes daily log files (kept 7 days) to `LocalState\logs` when installed, `%LOCALAPPDATA%\Morph\logs` in dev: startup, HEIC availability, every drop, every job result with timings and outputs, failures with full details, unhandled exceptions. Started from a terminal it also prints there, with drag and wheel detail. A tray icon offers Open logs folder and Quit Morph; the placeholder window is gone. New dependency: Microsoft.Extensions.Logging.Abstractions 10.0.0 (MIT) instead of the planned Serilog. `FileLoggerProviderTests`.
- MKV and AVI outputs and WMV input (developer's call, beyond CV-2): every video (MP4, MOV, MKV, WebM, AVI, WMV) converts to MP4, WebM, MKV, AVI, GIF and MP3 (118 rows). MKV copies streams it can hold and otherwise encodes H.264 + AAC; AVI is MPEG-4 Part 2 (`XVID` tag) + MP3 for old players. Streams are now copied one at a time: e.g. an MKV with H.264 + FLAC becomes MP4 by copying the video and encoding only the sound. WMV (ASF) is sniffed and read but not offered as an output (old WMV8 encoder: large, slow, patent questions). Golden tests compare durations against the shortest stream (ASF adds preroll to the container).
- Output under its real name from the start (developer's call, replaces JB-4's temp + rename): dropping a video on GIF makes `clip.gif` appear at once, and it fills in while converting; a failed or cancelled job deletes it. No more `.morph-….tmp` files. A video batch reserves all its outputs up front.
- Faster video: inputs already in the target's codecs are copied instead of re-encoded (H.264 MOV/MKV → MP4, VP8/VP9 → WebM; 0.3 s instead of 5 s for a 30 s 1080p clip). WebM (VP9) encodes about 5x faster (30 s 1080p: 61 s → 11.5 s) at nearly the same quality, files ~15% larger. `Ffmpeg.ProbeAsync` replaces `DurationAsync`. Fixed two flaky tests.
- Fixtures and golden tests (task 1.8): `build/gen-fixtures.cs` (file-based app, ~6 s) writes one sample per input format to `tests/fixtures/` (git-ignored): drawn 160×120 images (HEIC through WIC, skipped without HEVC), 1 s 320×240 video clips and 1 s audio tones. `GoldenTests` runs every conversion row of `capabilities.json` (104) through the real `Morph.Worker.exe` with the tool defaults and checks the sniffed format, image size and dHash (Hamming ≤ 6), media codecs, frame size and duration (±0.1 s). A row whose input has no fixture fails. CI generates fixtures before testing. The per-format theories in `ImagingEngineTests`/`MediaEngineTests` were removed (covered here).
- Toasts only on failure (developer's call, overrides JB-2): success, cancel and "already in that format" drops are silent; a failed drop shows the reason, Copy details, and Show in folder if other files converted. The progress bar and Cancel button are gone from the toast.
- Toasts (task 1.7): each drop shows one bottom-right Fluent card (JB-2). It shows progress and Cancel while running, "Saved photo.png" with Show in folder on success (closes after 6 s, stays while hovered), and the plain reason with Copy details on failure (stays until closed). A drop where every file is already in the target format says so. The toast never takes focus (`WS_EX_NOACTIVATE`). `Morph.Core.Jobs.JobGroup` combines a drop's jobs: progress weighted by file count, one Cancel for all, failed if any job failed. `JobGroupTests`. Checked by hand with a demo run: success, failure, running, cancel (no output left, no ffmpeg left, focus unchanged) and the nothing-to-do toast.
- Video and audio conversions (task 1.6): MP4, MOV, MKV, WebM and AVI convert to MP4 (H.264 + AAC 192k), WebM (VP9 + Opus) and GIF and MP3; MP3, M4A, WAV, FLAC, OGG and Opus convert among each other (104 rows in `capabilities.json`). GIFs go through a palettegen/paletteuse pass (15 fps, at most 480 px wide). Audio defaults are about 192 kbps (CV-4): MP3 192k, M4A AAC 192k, OGG Vorbis q6, Opus 128k; WAV and FLAC are lossless. A mixed drop of images and videos offers GIF and runs one job per engine. Tests: every new output from a generated clip, codecs and duration checked; audio to GIF refused.
- Image conversions (task 1.5): JPG, PNG, WebP, HEIC, AVIF, TIFF, GIF and BMP convert among each other (57 rows in `capabilities.json`). HEIC and AVIF are read with Magick.NET; AVIF and TIFF written with Magick; HEIC written through Windows (WIC) with the HEVC Video Extensions. Defaults: JPG and HEIC quality 90, AVIF 80. The App test-encodes a tiny HEIC at startup; without HEVC the HEIC wedge is not shown. R5 decided: Magick.Native is the replaceable LGPL unit; notices updated. Tests: conversions between formats, HEIC round trip (skips without HEVC), HEIC option disabled without HEVC.
- Worker protocol and engine host (task 1.4): `JobRequest.Parameters` carries each tool's defaults from `capabilities.json` (CV-4; JPG output now uses quality 90). The Worker checks inputs and the output folder before running an engine and fails with a plain message ("photo.jpg was moved or deleted."). `WorkerProtocolTests` run the real `Morph.Worker.exe` end to end: progress and outputs, parameters, missing input, unknown engine, a failure mid-batch leaves no outputs. Fixed two order-dependent `JobQueueTests`.
- Job queue (task 1.3): `Morph.Core.Jobs.JobQueue` runs jobs in parallel up to (logical cores − 1) with at most 2 media jobs at once (JB-1); a waiting media job never holds a slot image jobs could use. `JobHandle.Cancel` skips a queued job or stops a running one; a runner exception becomes a failed result. `Updated` reports queued/running/progress/result for toasts and history. Drops now go through the queue. `OutputNamer` (temp + rename, numbered clashes) was already in place from 0.4. `JobQueueTests`.
- Capability matrix (task 1.2): `Morph.Core/Capabilities/capabilities.json` (embedded) lists the wheel's tools, requirements and one row per (input, tool, engine); `CapabilityMatrix.OptionsFor` offers a tool only if it fits every dragged file (IX-3) and returns a disabled reason and fix link when a requirement is missing (CV-6), plus a beta flag (CV-5). The Convert wheel and the engine choice for a drop now come from the matrix instead of hard-coded lists; files already in the target format are skipped. Lookup goes by extension (`FileFormat.FromExtension`); the Worker still sniffs. `CapabilityMatrixTests`.
- File sniffing (task 1.1): `Morph.Core.Formats.FileSniffer` detects every CV-2 input format from a 64 KB header (JPG, PNG, GIF, BMP, TIFF, WebP, HEIC, AVIF, MP4, MOV, MKV, WebM, AVI, MP3, M4A, WAV, FLAC, OGG, Opus, PDF, ZIP, TAR, GZIP, WebVTT). Magic bytes win over the extension; the extension only breaks ties inside ISO-BMFF (MP4/M4A/MOV) and names plain-text formats (TXT, MD, HTML, CSV, SRT). ZIPs are opened to recognise DOCX/XLSX/PPTX; ODT/ODS/ODP come from the stored `mimetype` entry. `FileKind`/`FileFormat` records per PLAN §2. The Imaging and Media engines use it instead of their Phase 0 checks. `FileSnifferTests`.
- Repo skeleton (task 0.1): `Morph.slnx`, `Directory.Build.props` (net10.0-windows10.0.22621.0, C# 14, nullable, warnings as errors, x64), central package versions, `global.json` (SDK 10.0.403, Microsoft.Testing.Platform runner), `.editorconfig`.
- Projects: `Morph.Core`, `Morph.Engines`, `Morph.Worker`, `Morph.Overlay`, `Morph.App` (placeholder window), `Morph.Core.Tests`, `Morph.Engines.Tests` (xunit.v3 dependency-rule tests).
- GitHub Actions CI: restore, format check, build, unit tests.
- Drag gesture detector (task 0.2): `Morph.Overlay.Input.DragGestureDetector` on a dedicated STA input thread with a message-only window; raw mouse input (`RIDEV_INPUTSINK`, honours swapped buttons) detects drags past `SM_CXDRAG/SM_CYDRAG`; `WH_KEYBOARD_LL` is installed only during a candidate drag and reports Shift/Ctrl/Alt taps (≤ 400 ms, alone) and Esc. Drags are ignored when Morph is foreground or the cursor is hidden. `Morph.exe` prints gestures to the launching console (spike logging). CsWin32 0.3.367 added (build-time).
- `Morph.Overlay.Tests`: unit tests for the drag-threshold and modifier-tap state machines.
- Drop catchers and wheel (task 0.3): per-monitor invisible drop catchers (layered, alpha 1/255, no-activate, topmost) and the design A "Fluent ring" wheel (6 static wedges per wheel: Shift = Convert, Ctrl = Tools, Alt = Actions; light/dark; Windows accent on hover; 120 ms open animation). App is PerMonitorV2. A modifier tap shows the catchers; a file `DragEnter` within 250 ms opens the wheel at the cursor. Dropping on a wedge reports the item and paths (job wiring is task 0.4). Dropping on the centre or outside cancels, Esc closes the wheel and the drag continues. Windows are warmed up off-screen at startup.
- `WheelGeometryTests` for wedge hit-testing.
- First conversion end to end (task 0.4): dropping files on a Convert wedge (PNG, JPG, WebP, GIF, BMP) runs `Morph.Worker.exe`, which converts with Magick.NET and writes the output next to the original via a temp file renamed on success; a name clash becomes `photo (2).png`, nothing is overwritten. Virtual files (Outlook/Teams attachments, `FileGroupDescriptorW` + `FileContents`) are copied to `%TEMP%\Morph\in\<guid>\` and their output goes to Downloads.
- `Morph.Core.Jobs`: `JobRequest`, `JobResult`, `IEngine`, `EngineException`, `OutputNamer`, and a source-generated JSON context for the App ↔ Worker wire format (request on stdin, one result line on stdout).
- Input format is taken from magic bytes, never from ImageMagick's own detection, so script-like coders are unreachable. Magick memory capped at min(1 GB, 25% RAM), 30k px edge.
- Magick.NET-Q8-x64 14.17.2 (Apache-2.0); `package/THIRD-PARTY-NOTICES.txt`.
- Video conversion (task 0.5): MOV/MP4 → MP4 (H.264 + AAC) via the bundled ffmpeg.exe, from a new MP4 wedge on the Convert wheel. `-progress` output is parsed against the ffprobe duration and reported as job progress. The H.264 encoder is probed once by test-encoding one frame (NVENC → QSV → AMF → Media Foundation hardware → Media Foundation software; never libx264) and cached in `%LOCALAPPDATA%\Morph\cache\encoders.json`. The input demuxer is forced and only the `file` protocol allowed, so playlists can't open other files or URLs.
- Worker sandbox: each Worker runs in a Job Object (kill on close, 2 GB per process or 4 GB for video, at most 4 processes, below-normal priority, no crash dialog). Cancel closes the Worker's stdin; it stops ffmpeg and deletes temp files, and the Job Object is closed if it hasn't exited after 3 s. The Worker now reports progress lines before its result. `WorkerClient` moved to `Morph.Core`.
- `build/fetch-binaries.ps1`: downloads the LGPL FFmpeg build with a SHA-256 pin into `artifacts/binaries/`; CI runs it and tries to install Media Foundation.
- Packaging (task 0.6): `build/pack.ps1` publishes the App and Worker self-contained (ReadyToRun) into one layout with ffmpeg, assets and notices, packs `artifacts/Morph_x64.msix` with makeappx and signs it with the dev cert (`-NoSign` for CI and Store upload). makeappx/signtool come from the `Microsoft.Windows.SDK.BuildTools` NuGet package (build-time only). `build/dev-cert.ps1` creates the `CN=Morph Dev` cert in the user store and prints the one elevated command that trusts it. `package/AppxManifest.xml` (full trust, Windows 10 2004+) and placeholder logos.
- `build/size-check.ps1`: reports download/installed size and the largest files; fails over 120/300 MB. First numbers: 196.5 MB / 476 MB (over budget; FFmpeg and the WinRT projection dominate, see PLAN R3). CI packs unsigned, runs the size check report-only, and uploads the MSIX.
- First idle RAM measurement of the installed package: 53.6 MB private, 109 MB working set (PLAN R4).
- Tests: `MediaEngineTests` (progress parsing; MOV→MP4 codecs and duration; cancel kills ffmpeg and leaves no temp; non-video rejected; ffmpeg tests skip until binaries are fetched), `WorkerJobObjectTests`.
- Tests: `OutputNamerTests`, `ImagingEngineTests` (JPG→PNG, original untouched, no temp left; non-image rejected), `DragFilesTests` (descriptor parsing, unsafe names).

### Fixed
- Closing Morph's window now exits the app. The hidden wheel had become WPF's main window (the first window created), so the app kept running in the background with the wheel live.
- The Convert wheel no longer offers the format the files already are (dragging PNGs hides the PNG wedge; `.jpeg` counts as JPG). Mixed drags keep every wedge.
- Wheel glyphs in `App.xaml.cs` were garbled by an encoding round-trip in task 0.4; restored.

### Changed
- The wheel opens on press-and-hold instead of a tap: hold Shift/Ctrl/Alt for 200 ms during a drag. A quick tap does nothing; releasing the key closes the wheel and the drag continues. The probe starts on key down, so it finishes inside the hold.
- The wheel is smaller, matching the reference size: 240 DIP ring (was 400), 264 DIP window, smaller text and icons.
